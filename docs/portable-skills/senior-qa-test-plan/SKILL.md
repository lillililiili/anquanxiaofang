# Senior QA 测试计划

## 输出结构

测试计划应包含：

- 测试目标
- 测试范围
- 不测范围
- 核心风险
- 测试矩阵
- 关键用例
- 验收标准
- 回归清单
- 发布准入

## 覆盖范围

始终考虑：

- 正常主流程
- 状态流转
- 数据来源完整性
- 角色或权限行为，如相关
- 空状态、错误态、加载态、部分数据态
- 视觉布局和响应式表现
- 文件导入/导出，如相关
- 破坏性操作和二次确认
- 重复执行、缓存、旧数据风险
- 构建、打开、运行时冒烟检查

## 用例格式

使用紧凑表格：

| ID | 范围 | 操作步骤 | 预期结果 |
|---|---|---|---|

用例必须可执行，不写泛泛而谈的 QA 理论。

## 验收标准

验收标准要可度量：

- 数量
- 状态
- 可见文案
- 文件是否存在
- hash 或数据是否匹配
- 路由是否可打开
- 弹窗是否打开
- 状态是否变化
- 构建是否成功

## 发布准入

结尾给出清晰的 go/no-go 判断：

- 必须通过项
- 建议通过项
- 已知风险或后续项

如果功能涉及生成文件，必须包含来源校验和文件可打开性检查。
