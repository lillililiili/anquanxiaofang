# UI Audit Checklist

每次完成前端页面修改后，必须用本清单自查。

## Layout

- KPI 是否使用 CSS Grid。
- 10 个 KPI 是否为 5 列 x 2 行。
- 是否存在单个卡片孤立掉行。
- 图表卡片是否等高。
- 筛选栏、指标区、图表区、表格区 gap 是否统一为 16px。
- 左右栏比例是否稳定。
- 1440px 下是否无横向溢出。
- 1920px 下是否无大面积空白。

## Typography

- 页面标题是否为 22px / 600。
- 卡片标题是否为 16px / 600。
- 表头是否为 13px / 600。
- 表格正文是否为 13px / 400。
- 是否滥用 `font-bold`、`font-extrabold`、`font-black`。
- 是否滥用 `text-black` 或过深文字。
- 详情面板 label/value 是否区分清楚。

## Table

- 是否使用 `colgroup` 或稳定列宽。
- 表格是否在内部滚动容器中。
- 是否避免整页横向滚动。
- 长文本是否 ellipsis 或两行截断。
- 操作列是否稳定，不挤压主要内容。
- 是否没有文字竖排、重叠、大段换行。

## Interaction

- 所有主要按钮是否有实际反馈。
- 反馈可以是 Toast、弹窗、状态变化、数据变化或路由跳转。
- Toast 不能替代真正业务动作。
- 筛选是否可查询、可重置。
- 新增、上传、同步、导出、删除是否有清晰反馈。
- 删除类操作是否二次确认。

## Business

- 风险标签是否统一：高红、中橙、低绿。
- 主按钮是否统一蓝色。
- 日期时间是否使用原生日期/时间控件。
- 设备筛选是否同时有项目筛选。
- 隐患流程按钮是否按状态和当前 tab 显示。

## Delivery

- 运行 `npm run build`。
- 检查 1440px 与 1920px。
- 如有图表或复杂画面，截图检查是否重叠、空白、错位。
- 最终回复说明改了什么、验证了什么、是否有剩余风险。
