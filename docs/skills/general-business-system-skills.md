# 通用业务系统 Skills

这份文件把常见后台系统、SaaS 平台、业务管理端、演示系统中可复用的交互、表单、布局、媒体、前后端联动和交付检查规则整理成一组通用 Skills。可按需拆成独立 `SKILL.md`，也可以作为项目级开发准则引用。

## 1. 业务系统真实交互

```markdown
---
name: business-ui-real-interaction
description: 用于任何后台系统、业务平台、管理端页面开发，要求所有按钮、菜单、tab、下拉框都具备真实业务作用，避免只做静态展示或 toast 占位。
---

# 业务系统真实交互

- 所有可见按钮必须有自己的实际作用。
- 禁止按钮只弹 toast 但不改变任何状态。
- toast 只能作为真实操作后的反馈。
- 按钮动作应属于以下之一：
  - 查询、筛选、重置
  - 新增、编辑、删除、保存
  - 状态流转
  - 打开业务弹窗或详情抽屉
  - 页面跳转
  - 文件导入、导出、下载
  - 数据刷新
  - 调用后端接口
- tab 切换必须展示不同内容。
- 下拉框选择后必须立即影响页面数据。
- 表格行点击应能选中、展开详情或联动右侧信息。
```

## 2. 表单控件一致性

```markdown
---
name: form-control-consistency
description: 用于后台表单、筛选区、详情编辑区开发，统一日期、下拉、输入框、标签编辑等控件行为。
---

# 表单控件一致性

- 日期、时间、期限、时间范围必须使用原生时间控件：
  - `input type="date"`
  - `input type="datetime-local"`
  - `input type="time"`
- 不要用 select 或普通文本框模拟日期选择。
- 业务筛选区中，label 默认放在输入框左侧，避免上下排导致拥挤。
- 下拉框必须可选择，选择值不能被固定值覆盖。
- 可编辑标签、chip、关键词输入时，输入一个字后不能丢失焦点。
- 不要用输入内容本身作为 React key。
- 查询、重置必须真实改变筛选条件和结果数据。
```

## 3. 企业级布局质量

```markdown
---
name: enterprise-layout-quality
description: 用于企业级后台、SaaS、工作台、大屏式页面开发，保证页面整洁、信息密度合理、无溢出、无遮挡。
---

# 企业级布局质量

- 每次改页面后检查 1440px 和 1920px 宽度。
- 文本、图片、图表、按钮、表格、上传框不能超出外框。
- 外框缩小时，内部内容要自适应缩放、换行、截断或滚动。
- 不允许文字压住图片、按钮压住文字、表格挤出卡片。
- 表格列过多时使用容器内滚动，不能撑破页面。
- 卡片高度、表格高度、侧栏高度要视觉对齐。
- 页面不要过度拥挤，详情面板打开后主表格应自适应缩小。
- 避免无意义留白，尤其是演示页面和数据看板。
- 主操作按钮颜色保持统一，推荐蓝色。
- 不要出现 `Demo`、`演示数据` 等降低正式感的字样。
```

## 4. 主从详情联动

```markdown
---
name: master-detail-workflow
description: 用于客户档案、项目列表、订单列表、设备列表、告警列表等主表加详情面板页面。
---

# 主从详情联动

- 详情面板默认不主动显示，必须在用户选择一条数据后显示。
- 左侧点击哪条数据，右侧详情必须展示对应数据。
- 详情中的 tab 必须有实际内容。
- 关闭详情后，主列表应恢复完整宽度或保持合理布局。
- 详情中的按钮必须有效：
  - 查看大图
  - 添加标签
  - 查看更多记录
  - 查看合同或附件
  - 编辑、保存、删除
- 分页、每页条数、上一页、下一页、跳转页都必须真实改变列表。
```

## 5. 媒体素材与证据流

```markdown
---
name: media-evidence-workflow
description: 用于带图片、视频、音频、地图轨迹、附件上传下载的业务系统页面。
---

# 媒体素材与证据流

- 不允许出现灰色空白占位图、空视频、空音频。
- 优先使用本地静态素材或真实业务素材。
- 点击图片必须打开大图预览。
- 点击视频必须打开播放器或展开播放区域。
- 点击音频必须能播放、暂停，并展示转写文本或说明。
- 点击轨迹必须展示轨迹图或播放轨迹回放。
- 上传图片、上传视频、上传文件要区分类型，不要混成一个泛用上传框。
- 下载按钮必须生成文件或触发下载。
- 全部下载必须有打包下载反馈。
```

## 6. 前后端与 AI 联动

```markdown
---
name: frontend-backend-ai-integration
description: 用于需要前端调用后端接口、设备接口、AI接口或本地 mock 兜底的业务系统。
---

# 前后端与 AI 联动

- 前端页面不能只使用静态 mock，必须消费已实现的后端接口。
- 后端状态变化后，刷新页面应能看到最新数据。
- 设备类系统要验证登录、上报、实时状态更新。
- AI 分析类功能要包含：
  - 手动分析
  - 开始自动分析
  - 停止自动分析
  - 最新结果展示
  - 结果与表格、详情、标记联动
- AI 接口失败时必须 fallback 到 mock 或安全提示，不能让页面崩溃。
- 不要在前端暴露 API key。
- 后端日志不要打印完整密钥。
```

## 7. 业务系统交付检查

```markdown
---
name: business-webapp-release-check
description: 用于任何业务系统交付前的构建、接口、页面、按钮、布局和路由冒烟测试。
---

# 业务系统交付检查

- 每次交付前必须运行构建：
  - `npm run build`
  - 如有后台，运行 server build
- 检查核心接口是否可用。
- 检查核心路由不白屏。
- 检查浏览器控制台没有 error。
- 检查所有新增按钮是否有真实作用。
- 检查所有下拉框、tab、日期控件是否可用。
- 检查 1440px 和 1920px 布局是否溢出。
- 检查弹窗、抽屉、上传、预览、下载是否可用。
- 如果有 AI 或外部接口，必须测试失败兜底。
```
