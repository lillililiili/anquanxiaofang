# 消防与用电安全智能检查服务平台功能文档

## 1. 一句话说明

本平台用于辅助企业、园区、物业和第三方安全服务机构完成消防与用电安全检查。系统把“检查任务、现场取证、AI 识别、隐患登记、专家复核、整改复查、报告生成、风险看板”串成一条闭环。

当前项目是演示 Demo，主要用于产品汇报和流程展示。数据以本地 Mock 为主，后端提供轻量接口支撑智能安全帽、AI 识别和隐患草稿演示。

## 2. 平台解决什么问题

| 业务痛点 | 平台能力 | 结果 |
| --- | --- | --- |
| 检查任务分散，现场执行过程难跟踪 | 任务派发、设备绑定、执行状态查看 | 管理端能看到谁在查、查哪里、查到什么 |
| 现场取证不完整，隐患描述依赖人工经验 | 智能安全帽视频、图片、音频、AI 抽帧识别 | 形成可追溯的现场证据链 |
| 隐患判断标准不统一 | 知识库、隐患图谱、专家规则库 | 辅助给出依据、风险等级和整改建议 |
| 专家无法及时到现场 | 远程专家端视频会诊、截图标注、补拍提示 | 专家可以远程审核疑似隐患 |
| 整改闭环难管理 | 隐患台账、整改状态、复查销号、超期预警 | 每个隐患都有责任人、期限和闭环状态 |
| 汇报材料制作成本高 | 报告中心、证据链归档、报告导出 | 自动汇总检查结果和整改材料 |

## 3. 主要用户

| 用户 | 使用重点 |
| --- | --- |
| 运营管理员 | 看工作台、派发任务、跟踪整改、查看风险趋势 |
| 检查人员 | 接收任务，佩戴智能安全帽完成现场检查和取证 |
| 远程专家 | 查看现场视频和证据，对疑似隐患进行复核 |
| 企业/项目责任人 | 接收隐患整改要求，提交整改材料 |
| 系统管理员 | 管理设备、模板、角色权限、消息规则和系统配置 |

## 4. 业务闭环总览

```text
客户/项目建档
    ↓
创建检查任务
    ↓
绑定智能安全帽或采集设备
    ↓
现场检查与视频取证
    ↓
AI 识别疑似隐患
    ↓
隐患登记
    ↓
远程专家复核
    ↓
责任单位整改
    ↓
复查销号
    ↓
生成检查报告与风险看板
```

这条链路是系统演示的主线。其他模块，如知识库、隐患图谱、专家规则库、设备管理和预警中心，都是围绕这条主线提供支撑。

### 6.12 隐患闭环

隐患闭环是平台的核心业务模块，包含四个页面：

| 子页面 | 页面入口 | 主要功能 |
| --- | --- | --- |
| 隐患登记 | `/hazards/register` | 登记隐患信息、证据、风险等级、责任单位、整改期限和整改措施 |
| 隐患整改 | `/hazards/rectify` | 查看整改状态，提交整改材料，发起复查或退回整改 |
| 隐患统计看板 | `/hazards/dashboard` | 统计隐患类型、等级、状态、项目分布 |
| 超期预警列表 | `/hazards/overdue` | 查看即将超期、已超期、多次退回的隐患 |

隐患状态建议按以下顺序理解：

```text
待登记 → 待整改 → 整改中 → 待复查 → 专家复核 → 已销号
```

如果复查不通过，隐患会退回整改；如果超过整改期限，则进入超期预警。

## 7. 关键业务流程详解

### 7.1 任务派发

| 步骤 | 操作 | 产出 |
| --- | --- | --- |
| 1 | 在检查任务中选择任务 | 明确检查项目和检查内容 |
| 2 | 选择检查人员、时间和模板 | 形成可执行任务 |
| 3 | 绑定智能安全帽 | 任务与现场设备关联 |
| 4 | 确认派发 | 任务进入执行状态 |

### 7.2 AI 识别生成隐患

| 步骤 | 操作 | 产出 |
| --- | --- | --- |
| 1 | 打开智能安全帽现场端 | 查看现场视频 |
| 2 | 启动 AI 识别 | 系统定时抽取视频帧 |
| 3 | 后端分析图片帧 | 返回疑似隐患和风险等级 |
| 4 | 用户确认候选隐患 | 生成隐患登记草稿 |

### 7.3 隐患整改闭环

| 步骤 | 操作 | 产出 |
| --- | --- | --- |
| 1 | 登记隐患 | 形成隐患台账 |
| 2 | 指定责任单位和期限 | 明确整改责任 |
| 3 | 责任单位提交整改材料 | 形成整改证据 |
| 4 | 检查人员或专家复查 | 形成复查结论 |
| 5 | 通过后销号 | 闭环完成 |

### 7.4 专家远程复核

| 步骤 | 操作 | 产出 |
| --- | --- | --- |
| 1 | 专家查看视频和关键帧 | 掌握现场情况 |
| 2 | 对隐患进行确认或退回 | 形成专家判断 |
| 3 | 必要时发送补拍提示 | 补充证据 |
| 4 | 提交审核意见 | 回写隐患和报告 |

### 7.5 报告生成

| 步骤 | 操作 | 产出 |
| --- | --- | --- |
| 1 | 选择报告所需证据 | 形成证据链 |
| 2 | 选择隐患和整改材料 | 形成报告正文内容 |
| 3 | 点击生成报告 | 形成检查报告 |
| 4 | 导出报告 | 形成归档材料 |

| `/api/vision/latest?deviceId=...` | GET | 获取设备最近一次 AI 分析结果 |
| `/api/tasks/:taskId/hazard-candidates` | GET | 获取任务下的候选隐患 |
| `/api/hazard-candidates/:candidateId/register-draft` | POST | 将候选隐患生成登记草稿 |
| `/api/ai/generate-rectification` | POST | 生成整改建议 |
| `/api/index.php?ctl=config&act=get_config` | GET | 兼容设备配置拉取 |
| `/ws/device` | WebSocket | 设备登录和定位上报 |

## 11. 演示路径

建议按以下顺序演示，逻辑最清楚：

1. 打开运营工作台，介绍平台总览和核心指标。
2. 进入检查任务，展示任务派发和智能安全帽绑定。
3. 进入智能安全帽现场端，展示实时视频、设备状态和 AI 识别。
4. 将 AI 识别结果生成隐患登记草稿。
5. 进入隐患登记，补全隐患信息、责任单位和整改期限。
6. 进入大模型中台，展示依据检索、风险评分和整改建议。
7. 进入隐患图谱，说明隐患、风险、原因、依据和措施的关系。
8. 进入远程专家端，展示视频会诊、补拍提示和专家审核。
9. 进入隐患整改，展示整改材料、复查和销号。
10. 进入报告中心，生成检查报告并查看证据链。
11. 进入数据看板，展示风险画像和管理层汇总视角。
