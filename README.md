# 山东省国控企业管理有限公司消防与用电安全智能检查服务平台 Demo

这是一个用于商务汇报和产品路演的高质量前端 Demo，展示“智能安全帽 + 大模型知识中台 + 远程专家 + 隐患闭环 + 报告中心 + 风险画像”的完整产品闭环。

本项目是演示系统，不是生产系统；全部数据均为本地 mock data，不接后端、不接真实地图 API、不接真实 AI 接口、不接真实视频流。

## 技术栈

- React + Vite + TypeScript
- CSS 文件实现界面样式
- lucide-react 图标
- recharts 图表
- 本地 mock data：`src/data/mockData.ts`

## 运行方式

Windows 下可直接双击外层目录中的：

```text
一键启动消防与用电安全系统.cmd
```

脚本会在后台同时启动当前系统（5187）、独立主题 demo（5186）和共享后端（8080），随后分别打开当前系统和 demo 两个页面。端口固定，重复启动会复用本项目已有服务；如果端口被其他程序占用会报错，不会自动换端口或覆盖服务。

- 当前系统：http://127.0.0.1:5187/
- 主题 demo：http://127.0.0.1:5186/theme-prototype.html
- 后端健康检查：http://127.0.0.1:8080/api/health

启动器需要已安装 Node.js 和项目依赖；首次运行可在项目目录执行 `npm install`。命令行传入 `-NoBrowser` 可只启动服务而不打开浏览器。日志与进程状态保存在 `%TEMP%\fire-safety-inspection-system`，失败时可查看对应服务的日志。

需要关闭系统时，双击外层目录中的：

```text
一键关闭消防与用电安全系统.cmd
```

关闭脚本统一关闭当前系统、demo 和共享后端，校验项目路径、PID 和进程启动时间后再结束进程树；即使服务未响应也可根据已保存的记录关闭。不会结束其他项目服务，也不删除业务数据或日志；重复关闭可安全执行。

也可以使用命令行启动：

```bash
npm install
npm run dev
```

默认访问：

```text
http://localhost:5173/
```

同时查看当前系统和独立主题原型：

```bash
npm run dev:dual
```

```text
当前系统：http://127.0.0.1:5187/
主题原型：http://127.0.0.1:5186/
主题原型直达页：http://127.0.0.1:5186/theme-prototype.html
```

生产构建：

```bash
npm run build
```

公开演示地址（GitHub Pages）：

```text
https://lillililiili.github.io/anquanxiaofang/
```

推送到 `main` 后，GitHub Actions 会自动构建并发布静态 Demo；公开地址只包含前端演示数据，不连接本地共享后端。

- `/scenarios/hot-work` 动火作业与临时用电检查

## 推荐演示脚本

1. 打开 `/dashboard`，介绍平台定位：面向企业、园区、物业、商业综合体、第三方安全服务机构和政府购买服务场景，提供辅助检查、辅助研判、辅助取证、隐患闭环和报告生成能力。
2. 进入 `/tasks`，选择“齐鲁科技园配电室用电安全检查”，绑定“安全帽 SHM20250516001”，点击“确认派发”。
3. 进入 `/helmet-live`，展示第一视角画面、设备状态、GPS/北斗、电量、4G 信号、AI 疑似隐患和现场时间轴，点击“生成隐患”。
4. 在 `/hazards/register` 查看自动带入的现场证据、隐患类型、风险等级、责任单位、整改期限和整改措施，点击“提交隐患”。
5. 进入 `/ai-analysis`，展示图片识别、隐患图谱、检查依据检索、风险评分，点击“生成整改建议”。
6. 进入 `/expert`，展示专家查看现场视频与证据，对“配电箱未关闭”和“线缆裸露”给出专家意见，点击“提交审核”。
7. 进入 `/hazards`，查看待整改、整改中、复查中、专家复核、已销号等闭环状态，点击“提交复查”完成销号。
8. 进入 `/reports`，点击“生成报告”，展示《消防与用电安全检查报告》，再点击“导出PDF”查看模拟导出提示。
9. 进入 `/analytics`，展示园区/项目隐患热力图、隐患类型分布、风险等级分布、超期整改趋势和企业风险排行。

右下角提供“演示模式”按钮，可按上述 9 步快速跳转。

## 业务口径

系统定位为辅助工具，页面文案避免使用“行政处罚”“执法结论”“官方监管认定”等措辞。演示中建议使用“疑似隐患”“建议核查”“建议整改”“建议专家复核”“检查报告”“整改建议书”等表达。
